# Store releases: Run and Lift

Read by the mobile-store-release skill before every release of either app.
The skill holds the rules any app has; this file holds only what these two
apps have, and what their reviews have taught. Add to it whenever a review
teaches something.

## The apps, keys and builds

- `run` and `lift` in `.store-release.json`. One Apple developer team and one
  Play developer account serve both apps and other products, so the config's
  app list is the wall: never add another product's app here, and never use
  another product's keys for these.
- Keys: `~/.mgk-fitness/` (an App Store Connect key, App Manager, and the
  `mgk-fitness-play-publisher` service account), made for this project.
- Builds: Codemagic workflows `run-ios-release`, `run-android-release`,
  `lift-ios-release`, `lift-android-release`, started with
  `bash scripts/codemagic-build.sh <workflow> <branch>`. The Android
  workflows publish to Play's internal track: **nothing touches Play until
  they have finished.**
- The build number comes from the app's `pubspec.yaml` (`x.y.z+N`), not a CI
  counter. Bump it in a commit before building.

## Before a release

- **Render the store pictures from the build's code.** They are not in git.
  - Run: from `apps/mgk_run`,
    `flutter test test/plates/store.dart --dart-define-from-file=config/app_config.json`;
    then `cd design/store-shots && npm install && bash render.sh`; then
    `python tool/export_store_assets.py --check`. Copy
    `store-assets/derived/listing/{ios-still,play-still}` to
    `apps/mgk_run/screenshots/store/listing/` and
    `store-assets/derived/play-feature-graphic.png` to
    `apps/mgk_run/screenshots/store/`.
  - Lift: `apps/mgk_lift/design/store-shots` (`npm install`, `bash render.sh`;
    its README says where the set lands).
  - Dates and "today" in the pictures follow the day they are rendered.
- **Listing text.** Lift: `apps/mgk_lift/store/listing.json`. Run has no
  listing file yet; its copy is `apps/mgk_run/docs/app-store-listing.md` and
  `play-listing.md`.
- **Play release notes** are `apps/<app>/store/play-release-notes.txt`.
  Rewrite them for each release: Lift's still says "First release on Google
  Play".
- **The privacy policy is compiled into each app** (`legal_copy.dart`, pinned
  to `docs/privacy-policy.md` by a test) and published from
  `web/public/<app>/`. A build that changes what is collected, or how deletion
  works, changes the policy in the same build, and the web page must be live
  when the build goes for review.
- **Versions and branches**: a version is submitted once (Run's ADR-0046).
  At submission, tag `<app>/build-N` on the commit Codemagic built, promote
  only the submitted app to `main` (everything but the other app's folder),
  and move `develop` to the next patch version. `CONTRIBUTING.md` has the
  steps.
- Release policy: automatic on approval, and 100% on Play, unless Matthew says
  otherwise for a release.

## What review has taught these apps

- **2026-10-07, Lift 2.0.0, guideline 2.3.7:** "Free" on the store pictures.
  Run's pictures had the same words and were redrawn before its review.
  **Lift's pictures still print it** (16 October): `apps/mgk_lift/design/store-shots/src/shots.ts`
  tags three of the six `Free` and opens on "Free. No account.", and Lift's
  live Play listing shows that set. Change the tags and headline, redraw,
  and upload to both stores with Lift 2.0.1.
- **2026-10-16, Run 1.0.0, guideline 4 (Design):** the coach's first
  conversation asked "What should I call you?" after Sign in with Apple
  (reviewed on an iPad Air). Fixed in 1.0.1 (build 31): an Apple account never
  gets the name step, and an install that met the coach before signing in
  doesn't replay it. **Check Lift's flow against the same rule before
  2.0.1.**
- **2026-10-19, Run 1.0.1: approved**, three days after it was resubmitted,
  with the version, the *Run Coach* group and both subscriptions together
  (submission `7156a611`, four items). Resubmitting the rejected submission,
  rather than opening a new one, is what kept the subscriptions in it. Set to
  release on approval, it was on sale the same minute: Apple's email and the
  App Store's release time are 19 seconds apart.
- **2026-10-16, Run build 31, Android:** the Codemagic publish failed with
  "This edit has expired" because Play's status was polled once a minute
  during the upload. Rebuilt from `main` with nothing touching Play.
- **After attaching a build through the API**, App Store Connect's Resubmit
  button stayed grey until the version's Edit page was opened.
- **Subscriptions**: Run's group *Run Coach* (Run Coach Monthly, Run Coach
  Premium Monthly) went in with Run 1.0.0's submission and was approved with
  1.0.1 on 19 October; Lift's was approved with 2.0.0. Both are approved now,
  so a version goes for review without them. A new subscription is attached
  on the version page again, and never cancel a submission holding one.
- App Review uses the demo accounts set in each app's App Review details;
  their passwords are never in this repository, and entitlements are per
  app.
