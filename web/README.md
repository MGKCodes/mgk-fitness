# web — mgkfitness.mgkcodes.com

The suite's public pages. Legal documents and support today; marketing when
there is a product to market.

[`../NOTICE.md`](../NOTICE.md) for why the apps and the website are licensed
differently.

```
web/
├─ app/
│  ├─ page.tsx              the index
│  └─ run/support/page.tsx  Apple requires a support URL that resolves
├─ public/run/              GENERATED. Do not edit. See below.
└─ next.config.ts           the rewrites that give each document one URL
```

## The legal pages are generated, not written

`public/run/privacy-policy.html` and `public/run/medical-disclaimer.html` are
written by `apps/mgk_run/tool/build_legal_pages.py` from
`apps/mgk_run/docs/*.md`, and served **verbatim**. They are complete
self-contained documents with their CSS inline and no dependencies at all: no
webfont, no CDN, no analytics. A privacy policy that leaks the reader's IP
address to a font host before they reach the first line is the sort of thing a
regulator notices.

```bash
npm run legal      # or: cd ../apps/mgk_run && python tool/build_legal_pages.py
```

**Serving the generated bytes rather than a React component that reproduces
them is the whole point.** App Store review compares the published page against
what the app shows, word for word. The policy already exists three times over
(`docs/privacy-policy.md`, `legal_copy.dart`, this page); a component would be a
fourth, and the fourth is the one no test can see.

`apps/mgk_run/test/legal/legal_copy_test.dart` reads the files in `public/run/`
directly and fails if they stop agreeing with the app. Verified by breaking it
on purpose: renaming a sub-processor on the served page alone fails the suite.
That check is the reason the site lives in this repository rather than its own.

**They are committed on purpose.** Vercel builds from the repository and does
not run Python, so an uncommitted page is a deploy that serves nothing.

## Routing

| URL | Serves |
|---|---|
| `/run/privacy` | `public/run/privacy-policy.html` |
| `/run/medical-disclaimer` | `public/run/medical-disclaimer.html` |
| `/run/support` | a real page, not generated |
| `/run/terms` | nothing. The EULA is Apple's, hosted by Apple |

The `.html` paths redirect to the clean ones, so each document answers at one
address. A legal URL that works two ways is one that gets copied into App Store
Connect wrong, and that field cannot be corrected without a new submission.

## Deploying

A Vercel project of its own, separate from the studio site at `mgkcodes.com`:

- **Root directory** `web`
- **Ignored build step** `git diff --quiet HEAD^ HEAD -- .` so a Flutter-only
  commit does not trigger a deploy
- **Domain** `mgkfitness.mgkcodes.com`, a CNAME on `mgkcodes.com`

The subdomain is a DNS fact, not a repository one. Moving to a domain of its own
later is a CNAME change and nothing else.

## What is not here yet

- Lift's pages. They land beside Run's, from the same generator, when the
  rewrite ships.
- Marketing. Tailwind and a lint config come with it; scaffolding them for one
  support page would be furniture.
- Anything that needs a secret. If a contact form arrives, its key lives in
  Vercel's environment and never in this directory. The repository is headed
  for public.
